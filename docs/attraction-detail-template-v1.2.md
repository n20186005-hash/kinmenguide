## 1. 固定頁面順序

| 順位 | 區域 | 標題／內容 | 必要性 |
| --- | --- | --- | --- |
| 00 | 全站導覽 | Breadcrumb、站點導覽、頁內目錄 | 必要 |
| 01 | 景點首部 | 唯一 H1、短副標、可信時段、導航、加入行程 | 必要 |
| 02 | 實景主圖 | 圖片 alt、圖說、作者與授權 | 有可用素材才顯示 |
| 03 | 探索景點 | H2「探索景點」及 2–3 段客觀景觀／體驗介紹 | 必要 |
| 04 | 遊覽建議 | H3「遊覽建議」：時段、安全、可達性、天候 | 必要 |
| 05 | 景區特色 | H3「景區特色」：3–5 個特點 | 必要 |
| 06 | 關於景點 | H2「關於景點」：沿革、用途、文化意義，**明確呈現目前管理單位並連官方依據** | **第一內容區最後** |
| 07 | 基本資料 | H2「基本資料」：所在地、地址、坐標、管理單位、營運時間等 | **緊接關於** |
| 08 | 交通方式 | H2；H3 開車、大眾運輸、交通查詢 | 必要 |
| 09 | 路線地圖 | H2；入口、開放動線及位置導航。未有實測 GPX 則不顯示 | 有可靠資料時顯示 |
| 10 | 人文生態 | H2；依據事實選用人文、建築與工程、動物、植物、地形地貌、特色 | 適用時 |
| 11 | 遊客資訊與常見問答 | H2；依旅客實際需求組織可核實問答，答案和 FAQ JSON-LD 一對一一致 | 必要 |
| **12** | **行前規劃與深度遊覽** | **H2，承接舊版景點頁已存在的專題內容，子題以 H3 顯示** | **舊版有內容則不得遺失** |
| 13 | 周邊景點與順路行程 | H2；相鄰實際景點、餐飲住宿、延伸路線與站內連結 | 必要 |
| 14 | 查核日期與參觀提醒 | H2；資料查核日、例外公告、第三方定位 | 必要 |
| 15 | 資料來源與編輯說明 | H2；管理機關、官方交通、照片來源、勘誤入口、頁腳 | 必要 |

**核心不可移動的兩個相鄰關係：**
1. `探索 → 遊覽建議 → 景區特色 → 關於 → 基本資料`，其中「關於」為第一內容區最末模組。
2. `遊客資訊與常見問答 → 行前規劃與深度遊覽 → 周邊景點與順路行程`。**不可因統一資料化而刪減原有專題。**

「第一內容區」不是手機或桌面裝置上物理的一個 viewport。

### 關於景點中的管理資訊

- 明確寫「**目前管理單位：完整機關名稱**」，緊跟可點擊的機關原始來源連結，不只含混寫「政府管理」。
- 對於縣府所有、國家公園管理、委外維護、私人管理等，按官方資料區分「所有者」「主管機關」「經營者」「維護單位」；不可推定四者相同。
- 只拿到過期、轉載或疑似資料時，呈現「尚待確認」，不聲稱現行管理者。
- `基本資料` 同步顯示管理單位全稱；一旦異動，兩處與來源同時更新。

### v1.2：無實質內容的相冊一律刪除

- **景點相冊不再是固定頁面層級。** 若只有主圖、同圖重複展示或一段「目前只有一張照片」的說明，不輸出「景點相冊」H2、空白容器、圖片佔位或重覆署名正文。
- 原本的**景點主圖、alt、圖片圖說、攝影者、Creative Commons 授權與 Credits 連結**必須保留；刪除空相冊不等於刪除實景圖與授權聲明。
- 未來若累積至少兩張**不同畫面**、確實屬於該景點且有可用授權與圖說的實景照片，可以再評估是否使用獨立相冊。這是條件式內容，不能要求每站填充。
- 文章順序在沒有相冊時直接是：`人文生態 → 遊客資訊與常見問答 → 行前規劃與深度遊覽 → 周邊景點與順路行程`。導覽目錄也不得留有空相冊入口。

### v1.2：常見問答的資料與顯示規範

- FAQ 應回答實際旅客會遇到、且有依據的問題：開放時間、一般門票／特殊活動、交通支線、停車、無障礙限制、雨天安全、解說服務、廁所／電話、遊覽時間與順路行程等。
- **品質重於篇數**：內容充分的景點可安排 6–10 題，但沒有事實來源就只提供可核實的題目，不硬湊題數、不把同一答案換問法重複堆砌。
- 逐題區分「官方事實」「編輯建議」「動態資訊」，時間、價錢、班次、導覽場次只作一般參考；使用者參觀前應查看最新官方資料。
- **同源一致**：由內容資料 `faq[]` 的 `question`、`answer` 同步生成 Markdown 中的 `<details><summary>…</summary><p>…</p></details>` 與既有的 `FAQPage` JSON-LD，不得多出不可見問題或文字不符；以測試核對順序及字句完全一致。
- 不使用虛構的旅客提問紀錄、沒有來源的評分、當日是否開放、活動票價、全程無障礙保證、未核實的官方場次。

### 原頁專題保存規則（v1.2 新增）

- **先完整盤點原有的 H2/H3 與內鏈**，建立搬移對照；在 FAQ 後新增「行前規劃與深度遊覽」。
- 既有的行前查開放、值得觀察的風景、如何排入一天、拍照親子與天候、歷史或工程專題，要保持其獨立標題和實質正文。
- 可修正錯誤或過期內容，但不可僅把它們壓縮成首屏一句話、FAQ 或刪除。
- 舊的活動公告如需保留，明確標為**已結束的歷史公告**，不得冒充今天營業狀態。
- 增加新 H2 後，頁面目錄須能跳轉；單 H1、SEO、canonical、照片授權、加入行程、手機版都須保持正常。

## 4. 落地開發與驗收

- 原站：`n20186005-hash/kinmenguide`（Astro、Tailwind、TypeScript、Cloudflare）。
- 資料：`src/content/attractions/<slug>.md`；共用組件：`src/components/AttractionOverview.astro`；試點結構：`src/data/attraction-detail-pilots.ts`。
- 每次單站分支修改；其他景點 opt-in 狀態不變。
- Sol：較複雜的 Astro/TS、可視化結構、測試與差異處理。Luna：官方資訊比對、圖片授權、每段事實核對、獨立 QA。主 Agent 整合與發布決策。若無法調用子 Agent，保留其角色作檢查規則，不冒稱已使用。
- 必過測試：`pnpm validate`、`pnpm test:browser`；桌機與手機標題順序、**空相冊缺席且主圖署名仍在**、管理機關/來源連結、原專題保留、**可見 FAQ 題數/順序/答文與 JSON-LD 精準相等**、加入行程、其他欄目回歸。
- 發布前在 PR 確認 CI 和審查；發布後實際讀取正式網址並核實，再於 `docs/attraction-template-migration.csv` 記錄 VERIFIED。
- 完成一站之後才開始另一站；新對話接力須附來源、commit、PR、驗收、下一 slug。不能聲稱可自行開啟新對話。

## 5. 底線

不可捏造即時營業、虛構評分、來訪經歷、GPS 步行軌跡、物種、開放區域、路線分鐘數或假照片。對軍事與歷史景點避免娛樂化。站點始終須標明 Kinmen Guide 是第三方指南而非管理機關官方網站。
