# 商家資料維護

公開店家位於 src/data/businesses.json；這不是候選底冊。內部待查、原始快照、私人聯絡與GSC導出應保留於倉庫之外。不得將內部物件直接展開成頁面資料。

1. 以實際場所為單位建立kind:id。同品牌分店分開；核對地址、登記名、營業名與來源。
2. 來源優先官方或業者公開頁。checkedAt表示閱讀／核對日期，不能冒充資料發布日期、實地訪查或即時營業。閱讀搜尋快取時保留其限制於內部證據，公開描述不得寫即時保證。
3. 普通旅館和民宿須有官方登記名及字號；資格限定住宿須有官方資格資料。未知條件不填肯定設施，false也要有據。價格與供餐不推測。
4. 公開資料由src/lib/businesses.ts的嚴格Zod契約載入，schema或證據無效會阻擋build。普通名錄不生成薄詳頁；有實用決策內容才加入內容集合。既有攻略透過business-links.ts按分店對應，不改原URL。
5. filterFacts僅列已核實的true條件，保留限定說明。坐標需清楚來源及復用依據；沒有坐標不放地圖針，仍可用地址導航。
6. 關閉商家須標原因，不提供加入行程的推薦。若保留獨立關閉說明，先同步noindex和sitemap規則及驗證，不能僅改資料。
7. 區域關聯是規劃入口，不是附近距離承諾。步行／自駕順遊要有實際路線依據，不從直線距離生成時間。一般收錄與partners合作配置分開。
8. 執行pnpm validate及相關browser tests，確認店家卡片、舊收藏遷移、來源、登記、JSON-LD、內鏈、無JS和缺坐標行為。發布後另查CI、實際部署及線上內容，不把本地build視為上線。

維護隊列至少包含來源不可達、身份衝突、臨時公告到期、業者更正與照片授權。服務及恢復營業不能因過了某日自動推定。成效用相同時間窗口比較搜尋表現；目前未加入分析追蹤，不宣稱已有店家點擊事件數據。
